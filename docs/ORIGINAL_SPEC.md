# 1. プロジェクト概要

YouTube動画のURLを入力するだけで、動画に設定されているサムネイル画像を自動取得し、プレビュー確認後にダウンロードできるWebアプリケーションを開発する。

複数のYouTube動画URLをまとめて入力し、一括取得・一覧確認・個別保存・一括保存できる機能を実装する。

### 基本コンセプト

- URLを入力するだけでサムネイルを取得できる。
- 取得した画像は16:9に統一する。
- 最終出力サイズは1920×1080px。
- ダウンロード前に必ずプレビューを確認できる。
- 複数動画のURLをまとめて処理できる。
- 操作が直感的で、デザイン業務でも日常的に使えるUIにする。

# 3. YouTubeサムネイル取得仕様

## 3-1. 対応URL

以下のURL形式に対応する。

- https://www.youtube.com/watch?v=VIDEO_ID
- https://youtu.be/VIDEO_ID
- https://www.youtube.com/shorts/VIDEO_ID
- https://www.youtube.com/embed/VIDEO_ID
- https://www.youtube.com/live/VIDEO_ID

URLに含まれる余分なクエリパラメータやトラッキング情報は除去し、動画IDを正規化する。

無効なURLや動画IDはエラーとして扱う。

## 3-2. サムネイル取得方法

YouTubeのサムネイル画像URLを利用する。

取得候補：

1. maxresdefault.jpg
2. sddefault.jpg
3. hqdefault.jpg
4. mqdefault.jpg
5. default.jpg

上記の順番で取得を試みる。

重要事項：

- HTTPステータスを確認する。
- 404や画像取得失敗を検知する。
- 存在しないサムネイルを正常取得として扱わない。
- 実際の画像サイズを取得して判定する。
- 取得した画像の解像度を記録する。
- 最大解像度の画像を優先する。

サムネイル取得処理はサーバー側で実行し、ブラウザのCORS制限を回避する。

## 3-3. 取得画像の品質管理

YouTubeの元画像が1920×1080未満の場合でも、最終出力サイズは1920×1080pxに統一する。

ただし、拡大処理によって元画像以上の画質が得られるわけではないため、過度なシャープ処理や不自然な補間は行わない。

取得した元画像は加工前の状態でも保持できる設計とする。

# 4. 画像加工仕様

## 出力規格

| 項目 | 仕様 |
|---|---|
| 横幅 | 1920px |
| 高さ | 1080px |
| アスペクト比 | 16:9 |
| 形式 | JPEG |
| カラーモード | sRGB |
| 品質 | 95 |
| ファイル名 | 動画ID.jpg |

## 画像変換ルール

元画像の比率が16:9の場合：

- アスペクト比を維持する。
- 1920×1080にリサイズする。
- 不必要なトリミングを行わない。

元画像が16:9以外の場合：

- 中央基準で16:9にクロップする。
- 1920×1080に変換する。
- 画像の引き伸ばしは禁止。

元画像の加工に失敗した場合は、エラーを表示し、元画像を失わないようにする。

## 画像変換モード

将来の拡張を考慮して、以下の2モードを実装できる構造にする。

**STANDARD**
- 16:9に調整。
- 1920×1080に変換。
- 品質優先。

**ORIGINAL**
- 元画像を可能な限り保持。
- 元の解像度・比率の情報を保持。
- 必要な場合のみ変換する。

初期バージョンではSTANDARDを標準設定とする。

プレビュー画面では以下を表示する。

# 7. 一括取得機能

本アプリケーションの重要機能として実装する。

## 7-1. 入力

複数のYouTube URLを改行区切りで入力できるようにする。

例：

URL 1
URL 2
URL 3
URL 4

## 7-2. 処理

- URLを解析する。
- 動画IDを抽出する。
- 重複を除去する。
- 各動画のサムネイルを取得する。
- 画像を1920×1080に変換する。
- 結果を一覧に表示する。

## 7-3. 並列処理

複数URLを効率的に処理するため、並列処理を採用する。

ただしYouTube側への過剰なリクエストを避けるため、同時処理数は初期値5件程度とし、設定変更できる構造にする。

失敗したURLがあっても、他のURLの処理を停止しないこと。

## 7-4. 一括ダウンロード

取得済み画像をまとめてZIP形式でダウンロードできるようにする。

ZIP内部のファイル名：

VIDEO_ID.jpg

同じ動画IDの重複ファイルは作成しない。

ZIPファイル名：

youtube_thumbnails_YYYYMMDD_HHMMSS.zip

ダウンロード前に、成功件数と対象画像を確認できるようにする。

# 8. 保存・履歴機能

初期バージョンでは、取得画像の履歴をブラウザのIndexedDBに保存する。

履歴に保持する情報：

- 動画ID
- 動画URL
- 動画タイトル
- サムネイル画像
- 取得日時
- 元画像の解像度
- 出力画像の解像度

履歴画面では過去の取得画像を確認できるようにする。

機能：

- 履歴一覧
- 個別再ダウンロード
- 複数選択
- 一括ダウンロード
- 履歴削除
- 全履歴削除

ブラウザの容量制限を考慮し、保存容量を管理できるようにする。

# 9. エラー処理

以下のケースに対応する。

| エラー | 対応 |
|---|---|
| URL形式が不正 | URL形式を確認するよう案内 |
| 動画IDが不正 | エラー表示 |
| 動画が削除済み | 取得不可と表示 |
| 非公開動画 | 取得不可と表示 |
| サムネイルなし | 取得できる別サイズを探索 |
| 通信エラー | 再試行ボタンを表示 |
| 画像変換失敗 | 変換エラーとして表示 |
| ZIP作成失敗 | 再ダウンロード可能な状態を維持 |
| 重複URL | 重複として処理を省略 |

エラーはユーザーが理解しやすい日本語で表示する。

# 10. セキュリティ・実装上の注意

- URL解析時にYouTubeの許可ドメインを検証する。
- 任意のURLへのサーバーサイドリクエストを許可しない。
- SSRF対策を行う。
- リダイレクト先も検証する。
- 画像ファイルのMIMEタイプを検証する。
- ファイルサイズの上限を設定する。
- 画像処理時のメモリ使用量を管理する。
- 不正なファイルをZIPに含めない。
- YouTubeの利用規約および関連ポリシーを確認する。
- APIキーや秘密情報をクライアント側に露出させない。
